## Snippet Content

- Each finished snippet lives at `snippets/<category>/<slug>.md`.
- Published metadata, prose, identifiers, comments and examples are written in
  English.
- Every snippet is neutral and self-contained. It never names its source,
  source project, internal path or source-system identifier.
- Every entry explains the idea, problem, applicable conditions, mechanism,
  example, bottlenecks, trade-offs, limitations and related snippets.
- Published Python examples are verified before review; the verification
  infrastructure and evidence are not part of the repository.

## Publication Boundary

Apart from repository essentials (`README.md`, `LICENSE` and `.gitignore`), the
public repository contains only the English Markdown catalog under `snippets/`
and its generated Markdown navigation.

Authoring templates, schemas, registries, generators, configuration,
executable tests, fixtures, dependency environments and verification reports
are maintainer-local quality controls. They are excluded from Git and must
never be staged in a pull request.

## Pull Requests

Publish 5-10 independently reviewed snippet Markdown files per dedicated
branch and pull request. Generated indexes do not count toward that range.
Only snippet Markdown and generated Markdown navigation belong in a publication
pull request. Local contracts, utilities, tests, fixtures, configuration and
reports never enter a pull request.
